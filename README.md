# 面談予約システム (Vercel版)

Google Apps Script (GAS) で動いていた面談予約システムを、**Vercel で動く Web アプリ**に移行したものです。
データベースは**これまで通り Googleスプレッドシート**を使います。予約データの置き場所は変わりません。

- 保護者用画面: `https://<プロジェクト名>.vercel.app/`
- 職員用の管理画面: `https://<プロジェクト名>.vercel.app/admin`

---

## 1. 何が変わったか

| | GAS版 | Vercel版 |
|---|---|---|
| 画面の配信 | `doGet()` + `HtmlService` | `public/` の静的HTML |
| サーバー処理 | `google.script.run` | `/api/*` のREST API |
| データベース | `SpreadsheetApp`(同じスプレッドシート内) | Google Sheets API v4(**同じスプレッドシート**) |
| 認証情報 | スクリプト実行者のアカウント | サービスアカウント |
| メール送信 | `MailApp` | Resend または SMTP |
| リマインドの定期実行 | 時間主導トリガー | Vercel Cron |
| 管理画面のログイン | HTMLに直書き(画面上だけの鍵) | サーバー側で検証 + 署名付きCookie |
| 管理者メニュー | スプレッドシートのメニュー | 管理画面の「🛠 システム設定」タブ |

**シートの構造・列の並びは一切変えていません**。既存の予約データをそのまま読み書きします。

---

## 2. セットアップ手順

### 2-1. Googleサービスアカウントを用意する

Vercel からスプレッドシートを読み書きするための「ロボット用アカウント」を作ります。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る(既存のものでも可)
2. 「APIとサービス」→「ライブラリ」で次の2つを有効にする
   - **Google Sheets API**
   - **Google Drive API**(カレンダー出力に必要)
3. 「認証情報」→「認証情報を作成」→「サービスアカウント」を作成
4. 作成したサービスアカウントの「キー」タブ →「鍵を追加」→「JSON」でJSONファイルをダウンロード
5. JSONの中の `client_email`(`〜@〜.iam.gserviceaccount.com`)をコピーする

### 2-2. スプレッドシートを共有する

1. 予約データのスプレッドシートを開く
2. 右上の「共有」から、**2-1でコピーしたサービスアカウントのアドレスを「編集者」として追加**する
3. カレンダー出力を使う場合は、出力先の「カレンダー」フォルダも同じアドレスに**編集者**で共有する

> 共有を忘れると、アプリからは「スプレッドシートが見つからない」というエラーになります。

### 2-3. Vercelにデプロイする

1. [Vercel](https://vercel.com/) でこのGitHubリポジトリをインポートする
2. フレームワークの指定は不要(`Other` のままでOK)
3. 「Environment Variables」に `.env.example` の内容を参考にして値を設定する(→ 3章)
4. デプロイする

### 2-4. シートを準備する

デプロイ後、`/admin` を開いてログインし、「🛠 システム設定」タブの
**「シートの初期化・更新」**を1回実行してください。

- 校舎ごとの「予約枠」「予約データ」シートが無ければ作成します
- すでにある場合は、**不足している見出し列だけを補います(既存の予約は消えません)**
- GAS版の「職員メモ列を追加」「定員列を追加」「リマインド送信済列を追加」「面談記録列を追加」は、
  この1つの操作にまとまっています

続けて「📧 通知先シートを作成」を実行し、スプレッドシートの「通知先」シートの
C列に各校舎の担当者アドレスを記入してください。

## 3. 環境変数

`.env.example` に一覧とコメントがあります。最低限、次のものは必須です。

| 変数 | 説明 |
|---|---|
| `SPREADSHEET_ID` | スプレッドシートURLの `/d/` と `/edit` の間の文字列 |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | サービスアカウントのJSON鍵(そのまま貼り付け、またはbase64)<br>※ 代わりに `GOOGLE_SERVICE_ACCOUNT_EMAIL` と `GOOGLE_PRIVATE_KEY` の2つでも可 |
| `ADMIN_ID` / `ADMIN_PASSWORD` | 管理画面のログインID・パスワード |
| `SESSION_SECRET` | ログインCookieの署名鍵。`openssl rand -base64 32` などで生成した長い文字列 |
| `CRON_SECRET` | リマインドの定期実行を外部から勝手に叩かれないようにするトークン |

メール送信は `RESEND_API_KEY`(推奨)か、`SMTP_HOST` などのSMTP設定のどちらかを入れてください。
**どちらも未設定の場合、メールは送信されずログに記録されるだけ**になります(予約自体は正常に動きます)。

> ⚠️ `ADMIN_ID` と `ADMIN_PASSWORD` を設定しないと管理画面にログインできません。
> GAS版はIDとパスワードがHTMLに直書きされていましたが、Vercel版ではAPIが
> インターネットに公開されるため、サーバー側で検証する方式に変えています。
> **GAS版と同じパスワードは使わず、新しいものを設定してください。**

## 4. リマインドメールの定期実行

`vercel.json` の `crons` で、1日2回リマインドを送るよう設定しています。

```
0 1 * * *   → 日本時間 10:00
0 10 * * *  → 日本時間 19:00
```

Vercel Cron のスケジュールは **UTC** で書きます。同じ予約には1通しか送られないため
(送信済みフラグをスプレッドシートのL列に記録)、朝に失敗しても夜に拾える保険になっています。

> Vercel の Hobby プランは Cron の実行回数・時刻の精度に制限があります。
> 時刻どおりの配信が必要な場合は Pro プラン以上をご検討ください。

うまく送られないときは、管理画面の「🛠 システム設定」→「🩺 リマインドの診断」で
翌日の予約が送信対象になっているかを確認できます。

```
  index.html               保護者用

tests/                   テスト(npm test)
```

## 6. 開発

```bash
npm install
npm test                 # 77件のテストを実行(Googleへの接続は不要)

# ローカルで動かす場合
npm i -g vercel
cp .env.example .env.local   # 値を記入する
vercel dev
```

テストは Google Sheets API をインメモリのモックに差し替えて、実際のAPIハンドラと
ドメインロジックをそのまま動かしています。Googleの認証情報がなくても実行できます。

## 7. 移行にあたっての注意点

### 二重予約の防止
GAS版は `LockService` で排他制御していましたが、サーバーレス環境には同等の仕組みがありません。
代わりに「行を追記 → 直後に読み直して定員を超えていないか確認 → 超えていれば自分の行を取り消す」
という方式で、先に行が入った予約が残るようにしています。取り消された側には
「ちょうど同じ枠が埋まってしまいました」というメッセージが表示されます。

### タイムゾーン
Vercel のサーバーは UTC で動きます。「今日」「明日」「過去かどうか」の判定は
すべて `TIMEZONE`(既定 `Asia/Tokyo`)の壁時計を基準に計算しています。

### 日付・時刻の保存形式
新しく書き込む行は `2026-09-07` / `14:00` という文字列で保存します。
GAS時代に日付型で入っている既存データもそのまま読めるようになっています。

### カレンダー出力
サービスアカウントが作成したファイルは、そのサービスアカウントの所有物になります。
職員が閲覧できるよう、出力先フォルダ(`CALENDAR_OUTPUT_FOLDER_ID`)をサービスアカウントと
共有しておくか、`CALENDAR_SHARE_WITH` に閲覧させたいアドレスを設定してください。
フォルダへの作成に失敗した場合でも出力自体は行われ、画面に注意書きが表示されます。
